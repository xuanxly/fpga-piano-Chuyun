# D12间歇触控：D13自检与修复

用户实板反馈：运行D12/925A，有时一段时间所有触控都不灵敏，有时正常，不局限于单指/拖动/某页面。此报告不把数字自检通过写成已确认实板根因。

## 1. 已ACK的USB空DATA未更新包序号

原 `ws170120_usb_host.v` 只在成功且长度11时翻转DATA toggle。USB事务层已经对合法DATA（包括零长度）发ACK；设备会推进自己的toggle，而主机不推进会使下一条正常触摸被当重复包丢掉。连续空包还会累计失败并重新枚举，引起整段响应间断。

原源码定向失败：`reports/d13_toggle_before.log` 的 `ACKed ZLP did not advance USB toggle`。修复为所有成功的新DATA均推进toggle、长度11才提交HID；空包不再当通信失败。CRC错误不ACK、真正重复DATA仍忽略。

新测试检查空包后首条真实触摸立即接受、连续16个空包不重新枚举、不支持长度后恢复、重复DATA不重发、NAK不改包序号。见 `reports/xsim_d13_final_usb/tb_touch_poll_toggle.run.log`。

## 2. 把ScanTime当唯一包编号

原 `ws170120_reports.v` 仅靠相同ScanTime拒绝新首包，可能把同时间戳的新坐标或松手吞掉。USB层本已按toggle去重，HID时间戳不应代替这个序号。

原源码失败：`reports/d13_touch_before.log` 的 `new DATA with same scan time discarded: drag freezes`。修复为比较时间戳及完整内容；相同时间戳但数据变化仍接收。多触点帧仍以首包/续包组装，不发布孤立的按下续包；可信已知ID的孤立松手可释放。

定向测试及7302条已采集实屏报告回放通过，2039完整帧、五指、重复/回绕及最终释放保持。见 `tb_touch_same_stamp.run.log` 和 `tb_ws170120_reports.run.log`。

## 3. 缺续包导致误松手

原代码在下一帧尚未收齐且超过100ms时清除当前全部触点。这会让缺续包表现为持续按住的琴键突然释放。修复后丢弃不完整的新帧，保持上一完整状态；下一份完整帧、已知ID明确Tip0、USB拔出或会话看门狗仍能释放。不会凭孤立Tip1生成新按键。

这类保持策略不能补出丢失的数据；若设备真的丢失松手且之后没有任何有效帧、也未拔出，仍可能保留最后状态。对此应通过错误计数和实际设备报告继续定位，不能用周期性假松手掩盖问题。

## 4. 没有撤掉的保护

真实USB引脚模型重新检查SOF、描述符、CRC、重复DATA、NAK、五指/松手/拔出和手动长按启动。停掉USB时钟但保留LOCK的模型检查在3ms内释放触摸并让USB输出高阻，同时实体琴/屏幕/DAC继续运行。CH569和WS2812相关回归也通过。

修复前源码保存在 `reports/touch_before_sources/`，旧D12产品文件未改。D13没有自动烧录到实板。

## 5. 上板观察

使用最终通过审计的D13，核对User Code；TOUCH接J18，USBA-Switch朝FPGA，长按PCB3按钮约2秒启用。观察多次点击、持续按住、滑动、五指和松手。VERIFY的USB ERR统计轮询错误，SKIP统计已ACK但不是11字节的数据，均为十六进制饱和计数。

如果再次出现整段不灵敏，记录顶部诊断行、ERR/SKIP变化、右上连接指示及发生前后的操作。先判断是否重新枚举、物理拔出、CRC错误或报告异常，再决定下一项代码修复；不能直接承诺这三项已解释全部实板现象。
