## 独立参考和真实C服务

- `d13_audio_reference.json`：91300个效果输出与独立采样域模型逐值相等；实际测试音RTL输出4096点，32个预期频率由DFT独立核对。效果器最初的合唱RAM读延迟错误由此发现并修正。
- `host_media/test_0.log`、`test_1.log`：实际媒体C/FatFs服务连接模拟128GB FAT32/exFAT，各14455487项检查，覆盖五分钟录音、WAV回读/重采样、CSV与磁盘所有权/异常；EFFECTS保留录音，VERIFY进入时保存录音。没有操作真实卡。
- `tools/build_media_firmware.py --verify`：重新编译目标固件，并逐字节比较产品ROM，防止C源码和位流中的程序分离。
- `d13_toggle_before.log`、`d13_touch_before.log`：修复前USB空DATA与同时间戳拖动的可复现失败，不作为通过记录。修复前源码保留在`touch_before_sources/`。

## 最终物理实现审计

`tools/run_implementation.ps1`必须确认本次Tcl完整返回、新位流生成、Setup/Hold零违例及构建输入哈希未变。`audit_d13.py`还检查：

1. Setup、Hold、Recovery、Removal最小余量均非负，保留0.300ns额外建立预算。
2. D12的97项原始产品输入未改；D13实际构建输入与最终文件匹配。
3. 原58球位及整份启动配置保持，全部322封装行只允许新增E14/E13/C15三行变化，61个实际信号球位唯一。
4. USB两路IOBUF、CH569四路TBUF仍由直接INIT=1寄存器控制高阻使能，不能仅凭RTL复位代码推断上电状态。
5. 最终资源和User Code直接读取实际PnR及FS文件，发布包逐项读回核对，不沿用D12数字。

## 建议的首次实板验收顺序

1. 保留925A可回退文件，使用SRAM方式下载最终D13并核对User Code，观察POWER和HDMI持续正常。
2. 启用USB触摸；重复点击、长按、拖动、五指、松手，并观察VERIFY的USB ERR/SKIP及顶部诊断。若再次整段失灵，记录出问题前后计数，暂不把仿真修复当作根因已彻底排除。
3. 进入EFFECTS，逐个开启三种效果并调节，退出确认持续；回到录音确认保存带效果且监听音量不影响文件，文件播放保持原声。
4. 进入VERIFY默认静音，先选1声部低监听音量，再切4/8/16/28/32；观察实际采样计数、计算周期及错误标志。退出验证页应停止测试音。
5. 条件具备时接逻辑分析仪检查标准I2S，再用模拟输出做外部多频FFT和端到端延迟测量。先核对J13的1脚方向，不将数字引脚接无源扬声器。

本次未操作Programmer、FPGA Flash或CH569固件。所有“真实报告”指此前采集并保存的触控数据；“ADC模型/卡模型”不表示当前真实外设测试。
