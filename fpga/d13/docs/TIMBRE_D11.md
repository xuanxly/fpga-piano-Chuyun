# D11：拉开吉他与电钢琴的音色

目标来自试听反馈：D10的吉他、电钢琴相似，乐器特征不足。本版不是只更改音量或名称，而是分别改变频谱随时间的变化和音量包络。

## 两种声音

- **GUITAR（吉他）**：快速起音；琴体以基音、二次及少量三次泛音保持温暖，拨弦带出的高次泛音快速衰减；松键后较快制音。低音比高音衰减更慢。它是拨弦风格的模态合成，并非吉他录音或完整物理弦模型。
- **E-PIANO（电钢琴）**：圆润基音叠加随时间减弱的二倍频FM调制，以及独立3.5倍频铃音。金属感主要出现在起音，随后变柔和，琴体尾音显著长于吉他。不是声学钢琴或某个商业型号的采样。

电钢琴铃音有自己的32位相位累加器，避免将已回绕的基频相位乘非整数造成周期接缝。最高七键降低FM深度；既定音域和移调范围未扩大。新增的低音/高音两档衰减按键索引划分，不是逐音色采样库。

## 参数和实现

采样率48kHz，每声部32个50MHz系统时钟，28声部896个时钟。基础声部上下文保持64位；增加32×64位分布式RAM保存铃音相位、24位亮度包络及8位音量包络小数。没有乐器采样ROM，也不占TF读写带宽。

| 参数 | 电钢琴 | 吉他 |
|---|---|---|
| 满包络起音约值 | 2.67ms | 0.67ms |
| 前14键音量衰减时间常数 | 1.365s | 0.341s |
| 后14键音量衰减时间常数 | 0.683s | 0.171s |
| 亮度衰减时间常数 | 171ms | 43ms |
| 松键衰减时间常数 | 85ms | 21ms |

这些是数字递推系数的近似时间常数，不是测得的耳机响度或混响时长。低于包络阈值后清零；松键尾音在实际RTL测试中检查到完全静音。压力同时控制音量与亮度，力度变化经过原有平滑。没有额外混响。

钢琴、风琴、弦乐与冻结D10逐样本比较；切音色仍先淡出并清声部，按住的键须松开后再按。录音路径包含新音色，文件播放维持原文件声音。

## 复现与证据

1. `tools/run_d11_checks.ps1`：14项自检，包含新引擎、录音、触控与实体键、媒体页面、音频独占、USB启停及异常时钟回归，另含下述精确对照和声部隔离。
2. `tools/run_tests.ps1 -Optimize -WorkSubdir d11_quick -Benches tb_timbre_d11_equivalence`：其余三种音色7500次PCM及声部状态精确比较。
3. `tools/render_d11_audio.ps1` 后运行 `tools/analyze_d11_audio.py`：同一输入并行导出D10与D11各691200个PCM值，检查独立铃音、衰减、音高、最高移调音、释音、直流分量和幅值。
4. `tools/run_implementation.ps1`：全量Gowin综合及布局布线。必须保留原SDC与0.300ns附加建立保护预算，Setup/Hold零违例才交付。
5. `tools/audit_timbre_d11.py`：确认源码与构建一致，D10原件保留，45球位和322行封装配置一致，USB输出使能仍由INIT=1的DFFPE直接驱动。

新增 `sim/tb_timbre_d11_context.sv` 针对新分布式RAM交错触发28键，验证61600次独立铃音相位/亮度状态，以及重按和切换时完整清空，避免新音色状态串到其他琴键。

实际RTL的C4测试中，按住1秒后的RMS相对于0.1～0.2秒窗口：电钢琴约47.6%，吉他约7.2%。对10～90ms起点、2048采样短窗的归一化幅度频谱，两个乐器的平均余弦相似度由D10的0.899降为D11的0.837；该指标只说明这组C4测试的短音频谱分离有所改善，不能代替真实耳机听感。

声音文件来自实际RTL。`*_raw.wav`保留原始幅度；`*_matched_AB.wav`按“D10→0.5秒静音→D11”排列，每一版整段只施加一个响度匹配增益，便于比较音色，力度及衰减关系仍保留。测试顺序为C4长音、低音三和弦、最高移调音、轻按C4。未经过板上模拟电路；实际耳机效果需上板验收。

原理参考：Julius O. Smith 的 [Physical Audio Signal Processing](https://www.dsprelated.com/freebooks/pasp/) 中关于拨弦和频率相关阻尼的讨论，以及 John Chowning 的 [FM合成论文](https://yamahasynth.com/wp-content/uploads/images/fm_synthesispaper-2.pdf)。本实现为资源约束下的独立设计，不是直接移植论文完整模型。

## 物理实现选项

首轮默认算法下出现22个Setup和6个Hold违例，最差分别为-0.390/-0.039ns，未作为可下载文件发布。违规路径集中在既有UI、ROM及USB逻辑，音色引擎不是该轮报告中的失败路径。

最终采用高云手册SUG100-4.4.2E第112页明确支持的 **`place_option=2`**，保留 `route_option=0` 和 `replicate_resources=0`。与D10相比，GUI过程配置只有布局算法这一项变化；器件电压、启动/IO配置、CST/SDC、50/30/150/60MHz时钟和0.300ns附加建立保护预算不变。

独立候选B从同一份功能源码完整重建，经96个综合输入哈希、322行封装配置和device.cfg核对后并入主工程，追溯记录在 `reports/d11_physical_build_provenance.json`。最终Setup/Hold零违例，扣除附加保护预算后最小剩余 **+0.161/+0.165ns**；逻辑33123/59904，寄存器12611/60780，BSRAM117/118，DSP73.5/118。未选用的耗时候选已停止。
